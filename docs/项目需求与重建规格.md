# VC Intelligence Platform — 当前版本需求与重建规格

更新日期：2026-11-09。基线：M04D；本次实现分支：codex/upload-analysis。本文描述本次正式本地应用，不再将Demo当作已实现系统。精确源码与配置见同目录「重建附录-精确文件规格.md」。

## 1. 目标与已确认结构

面向个人/小团队投资研究人员，在Windows本机完成：上传BP → 自动建档与建议名称 → 手动修正名称 → 选择AI → 并行生成独立报告 → 项目库查看、PDF下载、项目追问。

主界面顶部包含「创建分析」「项目库」「知识库」，右上角为「模型设置」。浅灰背景、白色卡片、蓝色主按钮；无旧版左侧项目导航。保留旧后端和Streamlit代码用于兼容，但日常入口改为 http://127.0.0.1:8503/app/ 。静态界面由FastAPI同源提供，不需要Node构建或Streamlit服务。

## 2. 创建分析

直接上传单个PDF/PPTX/DOCX/XLSX，不要求先创建项目。限制25 MiB，空文件与非法类型拒绝。用户点击「识别BP」后，在本机保存、解析、建档。

自动名称为本地规则识别：优先前6片段的明确企业名称/公司名称/项目名称标签，再寻找前10行中的公司全称，无法识别则从文件名生成候选。明确显示命名来源，可手动修改，1—200字符，去首尾空白后不得为空。此命名不使用付费API，也不宣称通用语义识别。

解析完成后同页展示名称、文件状态、模型选择和生成按钮。解析失败、无文字保留资料和警告，但不得生成报告。PDF逐页、PPTX文本框与表格行、DOCX段落和表格、XLSX缓存单元格值；每段12000字符、最多5000段，超长文本拆分而不静默丢弃。当前不支持OCR。

上传请求使用request_id和内容SHA256幂等，同一请求同一内容返回原项目；不同内容返回409。浏览器以文件哈希保存本次会话上传标识，网络重试不重复创建。新分析重置界面，不删除历史资料。已有项目可从创建分析页顶部的紧凑选择栏恢复；当前项目ID保存在localStorage，页面刷新可恢复。密钥不进入浏览器持久存储。

## 3. 模型设置

首次初始化仅创建一个ChatGPT配置：OpenAI Responses接口，Base URL=https://api.openai.com/v1，模型ID=gpt-5-mini，最大输出6000 tokens，启用但无密钥。模型ID可手动修改；账号是否可调用由连接测试确认。

支持新增、编辑、停用、删除配置。字段：name（1—80）、model（1—200）、base_url（最多500）、api_kind（responses/chat_completions）、enabled、max_output_tokens（500—16000）、api_key（写入专用，最多1000）、clear_key。显示名不得重复。删除是软删除，不移除报告。删除所有模型后重启不重新添加默认项。

远程地址必须HTTPS，本机localhost/127.0.0.1允许HTTP；禁止URL中的用户凭据、查询串与fragment。编辑密钥留空表示保留；勾选清除则删除。地址变化时必须重新提供非空白密钥或显式清除旧密钥，不能把保存的密钥自动发送到新地址。

密钥使用Fernet加密，数据库保存密文，主密钥在data/secrets/master.key；接口只返回key_configured。保护范围为避免明文写库和误泄漏，不抵御能同时读取数据库与主密钥的本机用户。备份恢复时需同时保留业务库与主密钥；均不提交Git。

「测试连接」是显式付费操作，返回成功状态和用量，不回显密钥/模型原始响应。分析和追问仅显示已启用配置，无密钥不得提交。默认不存在模拟AI配置，正式界面不制造示例报告。

## 4. 分析任务

每批选择1—5个模型，服务内最多3路模型请求同时执行；不同模型分别持久化queued → running → completed/failed。一个失败不影响其他结果。用户手动点击单独重试，不自动重复付费调用。同项目已有活动分析时拒绝新批次；相同request_id重复提交返回原任务，变更模型集合返回409。

每个任务保存创建时项目名、模型名/ID/API类型、加密凭据及资料快照，避免排队期间设置变化影响请求。完成或失败后删除任务配置中的加密凭据，仅保留元信息。任务处理完成后保存finished_at。重启将遗留queued/running标为failed，不自动重发。

输入包括最多500来源片段、累计最多60000字符；人工未驳回事实最多20000字符且限定为已包含来源。保留document_name/location/id用于引用。超限设置context_limited，页面及PDF提示部分资料未分析。单次HTTP超时120秒，最大响应2 MB，禁用带Authorization的重定向。输出token上限按模型配置；本版不估算金额、不承诺金额预算上限，服务商费用另行管理。

Responses使用store=false和max_output_tokens，兼容接口使用Chat Completions及max_tokens。模型返回JSON：summary，sections[{title,body,source_ids}]，questions[]。本地验证字段类型/长度和引用ID属于本次输入；空回复、截断、拒绝、不合法JSON和伪造引用均使任务失败。提示词要求区分企业自述、模型推断与待核验事项，不编造财务数值或评分。引用ID有效不证明模型的语义解释正确，仍需人工复核。

## 5. 项目库与PDF

集中显示全部已完成新报告与旧M04D Mock报告，按时间倒序；可搜索报告时项目名、当前项目名和模型名。保留所有历史版本，每个模型独立报告。展示当前名称变化但正文始终保留生成时快照。

详情展示摘要、章节、来源折叠面板、尽调问题、用量和材料信息。真实报告与历史Mock清晰标记。主操作「下载报告PDF」直接返回application/pdf附件，不再要求用户通过打印窗口保存。A4排版，章节与来源原文、模型、时间、提示、页码齐全；所有模型字符串先转义。Windows使用系统宋体嵌入，其他系统可设置VC_PDF_FONT指向可嵌入中文TTF/TTC；无字体时退回CID字体，跨设备字体兼容性需自查。

## 6. 随时追问

创建分析和项目库均有固定追问按钮。必须先有当前项目与解析文字；无需先有报告。可选择已配置模型。打开已完成AI报告后默认关联该报告及对应模型，允许改为基于当前资料追问；历史Mock报告追问基于当前资料。

问题1—3000字符，每个项目一次只允许一个活动问题。消息以任务形式保存：问题、回答、模型、关联报告、时间、状态、错误、来源及用量。页面刷新后恢复。相同请求标识重复提交不重复调用，不同问题/模型/报告复用标识返回409。失败后重新发送，保留失败记录。

关联报告时使用报告输入快照和正文，否则使用当前项目资料。带入同项目最近10次成功对话，每个回答最多3000字符；截断显示history_limited。模型返回answer与source_ids，本地验证引用归属。跨项目报告引用返回404。所有上下文隔离按project_id，模型切换不混入其他项目。

## 7. 简化项目页面与兼容

2026-11-10按用户要求移除「资料与事实记录」区域。新版页面不再展示原文分页、人工事实新增或审核表单，也不再加载这些表单数据。生成报告按钮直接依据已解析文件及活动任务状态判断是否可用，不依赖事实表单。

报告和追问中的来源引用仍可查看。旧事实数据与API保留兼容，不执行数据删除；已有未驳回记录仍可进入后端分析快照。旧/api路由与M04D Mock历史报告保留。

## 9. 新API契约

|方法|/api/v2后缀|用途|
|---|---|---|
|GET/POST|/models|读取脱敏配置/新增|
|PUT/DELETE|/models/{id}|编辑/软删除|
|POST|/models/{id}/test|显式小额连接测试|
|POST|/imports|multipart file+request_id，返回project/document/name_source|
|GET|/projects|恢复已有项目|
|PATCH|/projects/{id}|更新name|
|POST/GET|/projects/{id}/runs|model_ids+request_id创建批次/查看任务|
|GET|/jobs/{id}|详情、结果、快照来源|
|GET|/reports|新报告与历史Mock的完成列表|
|GET|/reports/{id}/pdf|PDF下载；legacy=true选择旧报告|
|POST/GET|/projects/{id}/messages|model_id/question/report_id/request_id提交/读取对话|

新建上传201，任务202；缺失资源404，数据不合法422，状态或幂等冲突409。模型网络错误转换成不含服务商原始正文的提示。浏览器跨Origin变更请求拒绝403；Host只允许localhost/127.0.0.1（testserver用于测试）。应用无登录系统，必须只绑定loopback，不作为公网多用户服务部署。

## 10. 启动、测试与重建

Windows安装Python 3.11+，创建.venv，pip install -r requirements.txt。双击start_web.bat或python launcher_web.py。当前机器使用已有Python3.14的.venv314，因为下载版3.11被系统DLL策略阻止。SQLAlchemy限制2.0系列，ReportLab与cryptography为新增运行依赖。

首先在模型设置编辑ChatGPT，输入API Key，保存并测试连接；再上传BP生成报告。没有密钥时仍可上传、查看历史报告和维护事实，不允许假装生成真实分析。

重建时按附录中的相对路径恢复文件，安装依赖，以空data目录运行。附录不含业务资料、密钥、数据库和虚拟环境。完整测试：安装requirements-dev.txt，然后python -m pytest -q。浏览器测试服务tests/browser_fixture.py在8504使用独立data/browser-qa与外部模型替身；不得将它作为正式入口。

## BP 项目归档流程（2026-11-10，以本节为准）

- 一次 BP 导入建立一个项目；报告是该项目下的多个分析版本。既有项目、报告和追问完整保留，不迁移或删除业务数据。
- 创建分析页用于上传 BP、自动命名、手动改名和首次分析；顶部的“继续未完成项目”只列出没有成功报告的项目。
- 首份报告成功后自动切换至项目库，打开当前项目。创建页清除文件选择与已归档项目展示，再次进入显示新的上传入口。
- 失败、排队、运行中均不算归档；首份报告失败时保留创建页，可重试。多个模型中任意一个成功即可归档，其余任务继续运行并在项目内显示。
- 项目库按 project_id 聚合，一张卡片对应一个 BP 项目，显示当前项目名、报告数量和模型名称。搜索匹配项目名、历史快照名或模型名；导航只显示“项目库”，不显示项目数量。
- 打开项目后可查看 BP 资料、修改项目名、选择已配置的其他模型再次生成报告、重试失败任务、查看历史报告、下载 PDF 和继续追问。再次生成沿用原 project_id，不创建新 BP 项目。
- 历史 Mock 报告同样归属于原项目；历史报告保存生成时的名称和资料快照，不因项目改名而改写。
- 归档由已有成功报告推导，刷新后仍按相同规则分类；切换页面清空的是当前创建表单，而不是数据库中的项目。

验收：首次成功自动跳转；失败保留草稿；已归档项目不再出现在继续列表；多份报告聚合为一个项目；刷新后项目可打开；返回创建分析显示空白上传入口。浏览器测试使用模拟 API，不产生真实模型费用。
