## 推荐实施顺序

1. 报告速览：在现有项目内增加项目名片、简短判断、核心看点、关键风险和优先追问；详情与引用按需展开。新报告在原本的一次模型请求中生成结构化速览，不为展示额外调用模型。旧报告展示已有摘要，不用未经确认的规则推断缺失字段。
2. 报告对比：同一 BP 下选择2—4份报告，按相同字段显示结论、来源及信息状态。先扩展报告输出结构与版本兼容，再做字段对照，避免用章节标题强行匹配。无法匹配时明确显示未提供。
3. DOCX 报告导入：在项目内关联已有 BP、记录用户填写的模型标签和提示词批次，区分导入、真实在线生成和历史模拟来源。纳入同一项目报告列表与对比入口。
4. 可选质量评测：评分对象是模型报告质量，不能混同投资价值；先做简短评价与备注，再决定是否采用六维评分。

## 不能直接照搬的地方

- 上游 frontend 为 Streamlit；当前主界面是 frontend/web 的网页，不能直接替换组件。
- 上游 ImportedReport 与本地 AIJob 报告结构不同。需独立来源适配，避免报告 ID 冲突；历史快照保持原样。
- core/report_glance.py 中两份指定样本的短摘要是按文件哈希匹配的人工整理内容，其他报告仅做原文节选。这不是通用 AI 摘要能力，不能将样本内容用于其他 BP。
- 标准字段识别数和引用位置不代表事实已验证。比较时需保留原文、状态和来源。
- 上游 README 与测试提及 samples/M05B_reports，但当前克隆目录未包含 samples，不能声称样本验收已完成。
- 不重新引入用户已取消的人工事实维护步骤，不改变已确认的“创建分析 → 项目库”主流程。

## 核对源码入口

- frontend/glance_view.py、core/report_glance.py：速览与样本摘要规则。
- frontend/report_view.py、core/report_import.py：导入报告阅读、字段与解析。
- backend/report_api.py、backend/models.py：导入存储、关联检查、去重与质量评分。
- core/extraction/catalog.py：7类29字段字典。
- tests/test_m05b.py、tests/test_m05c.py：导入隔离、评分与速览测试意图。
